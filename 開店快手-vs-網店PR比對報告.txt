開店快手後台 vs 品牌網店 PR #1 功能比對報告
================================================

比對對象
--------
- 開店快手 雲端POS店管系統（pos.mybiz.net.tw）— SAM 現有店家在用的第三方 POS 後台，帳號 10559053 / aion
- acpaytesla/boxs-retail-tw PR #1（零售線第2階段：品牌網店）— 幫既有 POS 加一個消費者線上下單的網店，跟現有 POS 共用商品/庫存/訂單資料

兩者是不同系統：開店快手是現有的第三方後台管理系統；PR #1 是 ACpay 自己開發、要跟它對接的新網店前台。

二、PR #1（品牌網店）功能摘要
=============================
- 消費者線上商店：商品瀏覽 -> 購物車 -> 結帳，串接 ACpay 金流（URL Mode adapter，
  沿用 course-system 已驗證的 adapter）
- 資料庫新增 carts/cart_items（複合外鍵防跨店）、orders 新增付款欄位
- AcpayAioAdapter：簽章、XML、建單、查詢、退款、webhook 驗簽
- 公開商店 middleware（依 shop_id 隔離，用 URL 路徑而非內部用的 X-Shop-Id header）
  + 商品瀏覽 API
- 購物車 API（30 天過期、加購累加 / 改數量絕對值兩種語意分開）
- 結帳 API（交易內建單、檢查庫存足夠但不扣減；金流呼叫在交易外，絕不放在交易內）
- Webhook 處理（驗簽、三層冪等、原子扣庫存、inventory_movements 稽核表）
- 輕量 SEO 伺服器端預渲染
- 前端 Vue：商品列表/詳情、購物車、結帳、訂單確認頁
- PR 自己記錄的已知風險：結帳庫存檢查沒有列鎖（理論上兩人可能同時搶最後一件並各自被
  扣款）；需另外申請零售線自己的 ACpay 特店代號


三、差異與落差清單
==================
1. 商品主檔
   開店快手：系統管理 > 商品設定維護（PIC160）
   PR #1  ：說明共用同一份商品資料
   結論   ：[OK] 對得上，PR 說的「共用商品資料」應該就是這張表

2. 電子發票
   開店快手：完整合規模組，發票配號、參數設定、營業稅申報資料匯出
   PR #1  ：檔案清單完全沒有 invoice 相關程式
   結論   ：[落差] 網店訂單結帳完怎麼開發票，目前沒處理

3. 會員 / 積點
   開店快手：會員資料維護 + 會員點數報表，有完整 CRM/積點
   PR #1  ：carts/orders 沒有任何會員關聯欄位
   結論   ：[落差] 網店目前應是「免會員」結帳，會員無法在網店累點/折抵

4. 班別報表(X/Z帳條)
   開店快手：綁在收銀機交班流程
   PR #1  ：線上訂單不經過收銀機交班
   結論   ：[落差] 網店銷售額可能不會出現在既有的日報表/交班報表裡，
             總部要看網店業績得另開報表

5. 退貨/退款
   開店快手：獨立的「退貨資料查詢」報表
   PR #1  ：有做 ACpay 退款 API，但無證據寫回此報表
   結論   ：[落差] 線上退款可能查不到，跟門市退貨走不同軌

6. 庫存異動稽核
   開店快手：「庫存異動查詢報表/彙總表」
   PR #1  ：自建獨立的 inventory_movements 表
   結論   ：[落差] 兩套機制不是同一份，後台報表可能看不到「網店賣出」這個異動原因

7. 折扣/促銷
   開店快手：銷售折扣管理，會員折扣、數量/金額/部門/分類折扣、期間特價、組合商品
   PR #1  ：購物車/結帳程式無折扣計算邏輯
   結論   ：[落差] 網店可能用原價結帳，跟門市當下特價不一致

8. 組合商品（bundle）
   開店快手：有「組合商品設定」與對應銷售報表
   PR #1  ：商品瀏覽/購物車看起來只處理單一商品
   結論   ：[落差] 組合商品可能無法在網店販售

9. 併發風險
   開店快手：有盤點作業/庫存調整作業會即時改動庫存數字
   PR #1  ：結帳庫存檢查沒有列鎖（PR 自己承認）
   結論   ：[落差] 風險來源不只消費者搶購，後台盤點同時進行也可能撞到

10. 耗材訂購 / 廣告管理
    開店快手：跟供應商叫貨、POS 客顯廣告
    PR #1  ：未涉及
    結論   ：[OK] 跟網店無關，不用做

11. 成本管理 / 應付帳款 / 進貨管理
    開店快手：完整存在
    PR #1  ：未涉及
    結論   ：[OK] 跟消費者網店無關，不用做

12. 安全存量 / 呆滯庫存報表
    開店快手：存在，是採購決策用
    PR #1  ：結帳只檢查夠不夠賣
    結論   ：[OK] 本來就該分開，沒問題


四、建議跟 RD 確認的問題
========================
1. 網店訂單完成後，發票要怎麼開？是接既有電子發票模組，還是另外處理？
2. 網店結帳要不要串會員系統？如果要，會員折扣/積點怎麼在網店生效？
3. 網店的銷售額、退貨，總部要在哪張報表看到？需不需要另開一份「網店專用報表」，
   還是要讓既有報表也讀得到？
4. 網店扣庫存的 inventory_movements 稽核表，跟開店快手既有的庫存異動格式，
   是要對齊，還是本來就打算分開兩套？
5. 網店結帳有沒有打算套用門市現有的折扣/促銷規則（會員折扣、期間特價、組合商品）？
   如果不套用，行銷端知道嗎？
6. 結帳庫存檢查沒有列鎖這件事，加上後台本身也會跑盤點/庫存調整，兩邊會不會互相
   打架？需不需要加鎖？
